# 0.5.0 — 2026-11-16

## Changed

- **Breaking set (MINOR, closed-list item 2: a call that used to return a correct result is now rejected).** All on `treasury_dataframe_query`, all now refused as `system_catalog_access`:
  1. SQL that uses any of these 35 DuckDB internal metadata-view names — `duckdb_columns` `duckdb_constraints` `duckdb_databases` `duckdb_indexes` `duckdb_logs` `duckdb_schemas` `duckdb_tables` `duckdb_types` `duckdb_views` `pragma_database_list` `sqlite_schema` `sqlite_temp_master` `sqlite_temp_schema` `pg_am` `pg_attrdef` `pg_attribute` `pg_class` `pg_collation` `pg_constraint` `pg_database` `pg_depend` `pg_description` `pg_enum` `pg_index` `pg_indexes` `pg_namespace` `pg_prepared_statements` `pg_proc` `pg_sequence` `pg_sequences` `pg_settings` `pg_tables` `pg_tablespace` `pg_type` `pg_views` — in any of these roles: as a column alias (with or without `AS`, double-quoted, any case; inside a `register_as` query too), that alias in `ORDER BY`, a table alias, a subquery alias, or a CTE name. 0.4.0 answered each of these with the table's own rows.
  2. A direct read of `pg_am`, `pg_collation`, or `pg_tablespace` (`SELECT * FROM pg_am`). 0.4.0 returned the engine's metadata rows.
  3. A `register_as` naming any of those 35, or `sqlite_master`, `information_schema`, or `pg_catalog` (38 names, any case). It is refused before the query runs, and nothing is staged. 0.4.0 ran the query, returned its rows, and staged the table; 35 of the 38 stayed readable afterwards.
- **Fetch budget:** every request one tool call makes, retries and the 404 probe included, draws on one 50 s budget; an exhausted budget fails as `Timeout` with reason `retry_deadline_exceeded`.
- **`upstream_schema_changed`:** `treasury_get_debt`, `treasury_get_interest_rates`, and `treasury_get_exchange_rates` fail with this reason when the API drops or renames a field they request or read.
- **`treasury_get_interest_rates`** answers an empty match without the list of security types, and says so in a notice, when the API is unavailable or the call's budget runs out while fetching it.
- **`treasury_query_dataset`** trims endpoint, field, and sort names and accepts an endpoint path without its leading slash; the response echoes the normalized endpoint.
- **`fields` selections return distinct rows**, so `total_count` and `total_pages` count distinct combinations of the selected fields; the tool schema, README, and guide skill (1.1) now say so.
- **A 403 answer, HTML or not,** is `Forbidden`; 0.4.0 reported any HTML error page as `invalid_endpoint`.
- **`which_secret(...)`** is refused as `invalid_sql` (`canvas_reason: plan_operator_not_allowed`); it was `system_catalog_access`.
- **Framework SQL gate** (mcp-ts-core 0.13.19–0.13.21): constant-argument `range()` and `generate_series()` and `SHOW <table>` now run. A statement naming a file is refused as `sql_read_only`, and a parsed non-SELECT as `non_select_statement`.
- Sync framework skills, scripts, and the changelog template to mcp-ts-core 0.13.22; `.env.example` lists `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Fixed

- **Table cells and headers read back exactly** ([#24](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/24)): `treasury_query_dataset`, `treasury_get_debt`, `treasury_get_interest_rates`, `treasury_get_exchange_rates`, `treasury_dataframe_query`, and `treasury_dataframe_describe` share one encoder, so values holding `|`, backticks, emphasis markers, or line breaks parse back as their structuredContent values.
- **A `"null"` upstream value renders as `null` in every `content[]` cell.** 0.4.0 showed an empty cell in `treasury_query_dataset`, `$null` in `treasury_get_debt`, and `null%` in `treasury_get_interest_rates`; each cell now reads back as its structuredContent value.
- **Rejected queries are classified by status and a bare probe** ([#28](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/28)): a 404 on a request carrying `fields`, filters, `sort`, or a later page is resolved to `invalid_endpoint`, `invalid_field` (naming each unknown name and listing the endpoint's fields), `page_out_of_range`, or `invalid_filter`, and any 5xx, HTML or not, is a retryable `ServiceUnavailable`. 0.4.0 answered all of these `invalid_endpoint`.
- **`sort_field_not_selected`** is its own declared reason for a `sort` field missing from `fields`.
- **A page-1 query of `fields` alone whose every name exists** gets a retryable `ServiceUnavailable` instead of `invalid_filter`.
- **`treasury_dataframe_describe` `expires_at`** is described as fixed when the table was staged, not extended by queries and possibly cut short by a restart or the shared canvas's maximum lifetime ([#30](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/30)).
- **Concurrent first stagings share one tenant canvas** ([#33](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/33)); `treasury_dataframe_describe` lists only tables a query can reach.
- **`register_as` tables report their real column types** (`DECIMAL(20,2)`, `INTEGER`); 0.4.0 reported every column as `VARCHAR`.
- **A filter value, or an `in` member, containing a comma is refused before any request as `invalid_filter`, in every tool:** a scalar such as `1,000`, an `in` array member, and in the convenience tools `security_type`, a `countries` entry, `date`, `start_date`, and `end_date`. The API read the comma as the start of another condition and answered for a different query.
- **`invalid_field` on the legacy 400 route** carries a hint that works: a bare `treasury_query_dataset` call lists the endpoint's fields. The old hint named an `endpoint` input `treasury_list_datasets` does not accept.
- **Formatter output:** `treasury_query_dataset` renders endpoint and filter as code spans and headers as `Label (field_name)`, and an empty page returns a header-only table; enrichment notices in it and the three `get_*` tools are escaped. The missing-table recovery of `treasury_dataframe_query` names `mode=series` for their `canvas_id`.
