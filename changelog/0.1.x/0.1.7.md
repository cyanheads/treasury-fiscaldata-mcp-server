# 0.1.7 — 2026-08-13

## Added

- **`treasury_get_exchange_rates` gains `mixed_record_dates` and a per-row `effective_date`** ([#4](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/4)). `format()` renders `**Newest record date:**` plus a mixed-dates line when the rows span quarters, and the table gains an Effective Date column.
- **`treasury_get_exchange_rates` reports `retrieved_records` beside `total_records`** in `mode=series` ([#21](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/21)) — what paging actually walked, against the upstream match.
- **`treasury_dataframe_query` output field `row_count_capped`** ([#19](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/19)). True only when the query matched more rows than `row_limit`, read off the canvas's own `truncated` flag rather than inferred from `row_count === row_limit`.
- **`lint:packaging` check 11 — `server.json` / `package.json` description parity** ([#15](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/15)), with `package.json` as the source of truth. Exported as `checkDescriptionParity` and covered by `tests/scripts/lint-packaging.test.ts`.

## Changed

- **Package description shortened to 93 characters** ([#15](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/15)), clearing the 100-character registry-truncation warning, and propagated to `server.json`, `manifest.json`, both plugin manifests, and the README tagline.
- **`canvas_id` on the four data tools documents what it does** ([#13](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/13)): any non-empty value requests staging, the server assigns the `df_XXXXX_XXXXX` name, and it comes back in the output `canvas_id`. `treasury_dataframe_query`'s `register_as` drops the shape claim nothing enforces.
- **Every staging path names `treasury_dataframe_describe`, then `treasury_dataframe_query`** ([#6](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/6)) — runtime notice, `canvas_id` output describe, all four tool descriptions, and the server `instructions`. `treasury_get_debt`'s notice fires on registration rather than only when its preview was capped.
- **Tool descriptions dropped their hard-coded "as of" figures** ([#5](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/5)), which drifted on the upstream's publication schedule; `treasury_get_interest_rates` states "Rates are percentages, not basis points" instead. `treasury_get_debt`'s `total_debt` describe likewise swaps its example amount for the string's shape.
- **Debt coverage reads `1993-04-01`** ([#9](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/9)) across `treasury_get_debt`'s description, `start_date`, and `no_data_for_date` recovery, the dataset catalog, the server `instructions`, README, and `docs/design.md`. The endpoint holds nothing before it.
- **`CANVAS_PROVIDER_TYPE` documented as defaulting to `none`** ([#10](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/10)) in the README env table and `.env.example`, with the consequence stated: the `treasury_dataframe_*` tools reject every call until it is set to `duckdb`.
- **Exchange-rate scope reads ~165 countries** (from ~130) and the full history ~19,000 rows (from ~18,800) across the tool description, `countries`, the catalog entry, README, and `docs/design.md`.

## Fixed

- **`treasury_get_exchange_rates` `mode=latest` collapses on the currency, not the country** ([#16](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/16)). One row per `country_currency_desc` — greatest `record_date`, then greatest `effective_date` — applied on both paths, so an amended rate supersedes and a country holding two legal tenders keeps both.
- **`mode=latest` no longer takes a fixed 200-row slice** ([#17](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/17)), which had already dropped a currency from the 201-row `2025-03-31` quarter. Unfiltered, a one-row probe resolves the newest `record_date` and the fetch asks for that quarter by date; a country filter fetches at the API's 10,000-row ceiling.
- **`mode=series` walks `page[number]` to 50,000 rows** ([#21](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/21)) instead of keeping one 10,000-row page, and stages the canvas table with `truncated` / `maxRows` — `treasury_dataframe_describe` had reported a partial table as complete.
- **`treasury_get_interest_rates` and `treasury_get_exchange_rates` cap the inline `mode=series` array at 20 rows unconditionally** ([#18](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/18)). The cap used to apply only when a canvas absorbed the remainder, so the default install returned the whole fetched page. `mode=latest` stays whole in both.
- **`treasury_dataframe_query` discloses a `row_limit`-capped result** ([#19](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/19)) through `ctx.enrich.truncated` and a `— capped at row_limit; more rows matched` header. Guidance names `row_limit` and `register_as`, never `preview`, which cannot move a cap it already sits at.
- **`treasury_query_dataset` rejects empty filter values at the input schema** ([#14](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/14)). `minLength: 1` and `minItems: 1` on both union arms — an empty scalar reached the API as a bad *operator*, while an empty list or member was accepted and silently not applied.
- **`treasury_query_dataset` composes its enrichment notices into one flush** ([#6](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/6)). The off-catalog warning and the zero-rows guidance both wrote the last-wins `notice` key and erased each other; staging that produced no table now says so.
- **`treasury_dataframe_describe` omits unset parameters from its `Params:` line** — `JSON.stringify(undefined)` interpolated the literal text `undefined`, which read as a filter the dataframe had been built with.
