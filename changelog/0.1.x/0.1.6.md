# 0.1.6 — 2026-08-12

## Added

- **`.github/` community-health files** — `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `FUNDING.yml`, `SECURITY.md` — plus `.gitattributes` for LF normalization and generated-file diff collapsing.
- **`tests/services/fiscal-data-service.test.ts`** — service-layer coverage for the request deadline, retry classification, and 400 reason mapping.

## Changed

- **`bunfig.toml` supply-chain guards** — a 3-day `minimumReleaseAge` hold with `@cyanheads/mcp-ts-core` excluded, plus the `@socketsecurity/bun-security-scanner` install scanner. Configuring a scanner disables Bun's auto-install.
- **`Dockerfile` pins `oven/bun:1.3.14`** on both stages, installs with `--ignore-scripts` behind a BuildKit cache mount, and adds `--omit=dev --omit=peer` to the optional OTel install so it stops pulling the framework's full optional-peer set into the image.
- **devcheck's `Outdated` gate** fails only on what `bun update` would actually move — peer rows and versions held back by `minimumReleaseAge` no longer count. `check-dependency-specifiers` now scans `overrides` as well.
- **`bundle` strips `@duckdb/node-bindings-*` platform slices** alongside dependency-shipped agent docs, and `lint:packaging` fails a bundle still carrying either; a packed bundle otherwise runs only on its build host and exceeds the 25 MB registry cap.
- **`tree` honors directory-only ignore patterns** (`/data/`, `.claude/`), which match only when the tested path carries a trailing slash.
- **`tsconfig.json` typechecks `tests/`** under `noEmit`, with emit moved to `tsconfig.build.json`.
- **Package description** rewritten across `package.json`, `manifest.json`, and both plugin manifests; `manifest.json` gains `license`.
- **Agent skills re-synced** to the framework's 0.11.5 versions.

## Fixed

- **`treasury_get_debt` `mode=series` walks `page[number]`** up to 50,000 rows instead of taking a single 10,000-row page ([#7](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/7)). A new `retrieved_records` output field reports what was actually fetched, so no response claims the upstream `total_records` it never retrieved.
- **`treasury_get_debt` declares its 20-row `series` array a preview** ([#2](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/2)) through a new `enrichment` block (`truncated` / `shown` / `cap` / `notice`) and a `(showing X of Y)` line in `format()`. Compare `series.length` against `retrieved_records` to detect the cap from the payload alone.
- **`FiscalDataService`'s deadline bounds the whole exchange, not just the headers** ([#8](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/8)). Both `response.text()` reads now run under it, and an expiry classifies as `Timeout` — distinct from a `ctx.signal` cancellation, which still short-circuits the retry loop.
- **4xx responses fail on the first attempt** ([#11](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/11)). Retryability keys on the status class through `httpStatusToErrorCode` (408/425/429 stay transient) rather than on which 400 message pattern matched; an out-of-range page raises the new `page_out_of_range` reason, declared on `treasury_query_dataset`.
- **Rerouted errors carry their contract's declared recovery hint** ([#3](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/3)). `treasury_query_dataset` and `treasury_dataframe_query` pass `ctx.recoveryFor(reason)` at the throw site and chain the original as `cause`; the SQL-gate reason set now derives from the framework's `SQL_GATE_REASONS`, closing an `invalid_sql` fall-through.
- **`treasury_dataframe_query` declares `missing_table` and `invalid_query_bounds`** ([#12](https://github.com/cyanheads/treasury-fiscaldata-mcp-server/issues/12)). Both reached clients with the framework's own wording — `registerTable()`, `describe()`, `rowLimit` — and are restated in this server's tool and parameter names.
- **Guidance names the constraint that actually applied** — whichever of `preview` / `row_limit` bound in `treasury_dataframe_query`, the date range only in `treasury_get_interest_rates` `mode=series`, and the omitted input for `treasury_get_debt` `mode=date` with a blank `date`. An empty series renders `_No debt record matched._` rather than bare `$` amounts.
